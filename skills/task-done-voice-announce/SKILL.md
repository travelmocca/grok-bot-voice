# 任务完成语音播报

安装、自检、自动接入步骤见仓库根目录 [README.md](../../README.md)。本文件只规定**何时播、播什么、怎么播**。

## 何时用
- 一项委托任务**已完成**（结果已验证可交付），需要让用户立刻知道
- 敲定了会长期生效的偏好/配置结论（例如改开场话术、播报规则）

不要用于：纯问意见、闲聊追问、还在进行中的中间步骤、仍在等待用户确认的半成品（除非用户明确要求「用声音说一下」）。

同一任务同一结果**只播一次**；重试失败后的最终成功可再播一次。

## 话术
1. 开场固定：「滴滴滴」（提醒声，念三声「滴」）
2. 接着一两句口语摘要：结果怎样（可说「我已经完成了」）；不要全文播报
3. 完整句子；不要列表、markdown、路径堆砌；摘要默认避免念出密码、完整密钥；姓名/金额仅在用户任务本身需要时带一句

## 在哪播
- 仅在用户已连接的 **Mac** 上外放
- 用户从某台机器发来消息时，默认用那台的 `machineId`
- 若无可用 Mac / 本地执行被拒：跳过外放，聊天文字交付并说明原因

## 怎么播（按优先级）
1. **优先**：`~/.grokbot-tts/announce.sh`（由本仓库 `scripts/announce.sh` 安装）
   - **文本经 stdin 传入**，不要把摘要拼进未转义的 shell 双引号：
     `printf '%s\n' '滴滴滴。我已经完成了……' | ~/.grokbot-tts/announce.sh`
   - 音色：`GROKBOT_TTS_VOICE`（默认 `zh-CN-YunxiNeural`）
2. **脚本不存在时**：先按 README 从本仓库复制脚本；临时等价：用 stdin/`--text` 调 `edge-tts` 写到**唯一临时 mp3**再 `afplay`（不要固定覆盖同一个 `last-announce.mp3`）
3. **再后备**：`say -v Tingting -r 180 -- "……"`（或用户指定系统音色）
4. **仍失败**：聊天文字交付同一摘要，说明外放失败；不要阻塞可见交付物

合成/播放应有超时意识；失败后最多再试一次 `say`，然后继续文字交付。

## 选音色
- 优先适合工作：清楚、稳、少抢戏
- 不为特色选花活/卡通音色
- 用户已指定默认音色时严格使用

## 与自动触发的关系
本 skill **不是**宿主 hook。是否在任务完成后自动加载本 skill，取决于：
- 助手偏好/人设记忆（Grok Bot 常见做法），或
- 平台若提供「任务完成」事件再绑事件

助手在适用时机应主动加载并执行；不要等用户每次 `@`。也不要把「已写入记忆」说成「系统级 hook 已生效」。

## 完成后
聊天里仍用简短文字交付结果（链接、附件等）；外放只是摘要，不替代可见交付物。
